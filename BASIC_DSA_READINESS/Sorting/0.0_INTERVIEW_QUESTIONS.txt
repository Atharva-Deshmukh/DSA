--- BASICS ---------------------------------------------------------------------

Q: What is sorting? Why does an SDET care?
- Arranging elements in a defined order (asc/desc).
- Testing use: compare API responses deterministically, spot duplicates, verify UI tables/lists
  are ordered, make assertions order-independent (sort both sides before deep-equal).

Q: Why is O(n log n) the limit for comparison sorts?
- A comparison sort can only know how to sort based on "is a[i] > a[j]?". Nothing else. 
  So, it just checks how many "is a[i] > a[j]?"s
- There are n! permutations of n distinct array elements
- For each of the n elements, there is a decision tree (n! leaves -> log(n!) ~ n log n). This is purely mathematical.
- This TC can be beat by Non-comparision based algos: Counting / Radix / Bucket Sort -> O(n)

Q: Which sorts are in-place (O(1) extra space)?
- Yes: Bubble, Selection, Insertion, Quick (ignoring O(log n) recursion stack)
- No : Merge O(n), Counting O(k), Radix O(n+k), Bucket O(n).

Q: Stable vs unstable? Why care?
- Stable:
  --> equal keys keep input order. Needed for MULTI-LEVEL sort (sort by dept, then salary -> dept grouping survives).
  --> Bubble, Insertion, Merge, Counting, Radix, Tim Sort.
- Unstable: 
  --> Quick, Heap, Selection, Shell.
  --> Make any sort stable: sort (value, original_index) with index as tie-breaker.

Q: Why do languages use HYBRID sorts?
- No single algo wins everywhere. Tim Sort = Merge + Insertion (runs), used by Python sorted(),
  V8 Array.sort(). Insertion for small chunks, merge for big.

--- MERGE vs QUICK ----------------------------------------------------------------

Q: Merge Sort vs Quick Sort
            | Merge                      | Quick
  Time      | O(n log n) always          | Avg O(n log n), Worst O(n^2)
  Space     | O(n)                       | O(log n) stack
  Stable    | Yes                        | No
  Best for  | Linked lists, huge/external | Arrays, in-memory, fast in practice

Q: Why Merge Sort for linked lists?
- Needs only sequential access + O(1) splice to merge -> no extra array needed, stays stable.
- Quick Sort needs random access for pivot/partition -> poor on lists.

Q: Why Quick Sort for arrays?
- In-place, random access is O(1), better cache locality than Merge's extra array.

Q: Quick Sort worst case and how to avoid it?
- O(n^2) when pivot is always min/max (already sorted / reverse sorted input).
- Avoid: randomised pivot

Q: When prefer Insertion Sort?
- ONLINE/streaming input OR Nearly sorted data (inner loop barely runs -> O(n))

Q: When prefer Counting Sort?
- Integers in a small known range k (k ~ n)

--- JS / TS SPECIFICS (the ones that actually get asked) --------------------------

Q: What does JS Array.sort() do by default?
- Converts elements to STRINGS and compares UTF-16 code units.
  [10, 9, 1].sort() -> [1, 10, 9]   <- classic bug / interview gotcha.
- Always pass a comparator for numbers: arr.sort((a, b) => a - b).

Q: Is Array.sort() stable? Algorithm? Complexity?
- Stable - GUARANTEED since ES2019 (V8 >= 7.0 uses Tim Sort). Older engines: not guaranteed.
- ECMAScript does NOT mandate the algorithm, only stability + comparator semantics.
- O(n log n) typical.

Q: Does sort() mutate?
- ARRAYS only: sorts in place and returns the SAME array reference.
  Non-mutating: arr.toSorted() (ES2023) or [...arr].sort().
- STRINGS have no sort() (immutable). Sort via s.split("").sort().join("") -> NEW string,
  original untouched. (Same trick for Is Anagram.)

Q: Sort strings / locale?
- Default is code-unit order ("B" < "a"). Use a.localeCompare(b) for human order;
  localeCompare(b, undefined, { numeric: true }) for "file2" < "file10".

Q: Sort objects by multiple keys?
- (a, b) => a.dept.localeCompare(b.dept) || a.salary - b.salary   // first non-zero wins

--- TESTING ANGLE (SDET twist - expect a follow-up on EVERY coding answer) ---------

Q: How do you test a sorting function?
- Empty, single element, two elements, already sorted, reverse sorted, all equal, duplicates,
  negatives / zeros, mixed types or strings-as-numbers, nulls/undefined, very large n (perf),
  stability check (equal keys keep order), input not mutated (if contract says so).

Q: How do you assert an API/UI list is sorted?
- Don't hard-code expected order. Pull the field, compare against a sorted copy with the SAME
  comparator the product claims (asc/desc, case, locale, nulls). Or check every adjacent pair.

Q: Sorting + pagination - common bug?
- Sorting by a NON-UNIQUE field (createdAt) -> ties reorder between pages -> duplicates/missing rows.
- Fix/test: sort by a unique deterministic key or composite (createdAt + id); test page boundaries.

Q: Sorting in distributed systems - what to test?
- Multiple nodes / shards / parallel writes -> clock skew, per-shard order != global order.
- Test with composite keys (timestamp + unique id), cross-shard merge, consistency after retries.

Q: Sorting with nulls?

  and asc/desc.

  Nulls-last comparator (works for asc and desc, numbers or objects):
    const nullsLast = (a, b) => (a == null) - (b == null) || a - b;      // asc
    const nullsLastDesc = (a, b) => (a == null) - (b == null) || b - a;  // desc
    users.sort((x, y) => nullsLast(x.age, y.age));
    // (a == null) covers BOTH null and undefined. true - false = 1 -> a goes after b.
    // Swap the subtraction order for nulls-FIRST.

- DB behaviour differs: Postgres ASC -> NULLS LAST, DESC -> NULLS FIRST (flips); MySQL ASC ->
  NULLs FIRST. Test: API sorted asc vs desc, nulls should land where the SPEC says, not where
  the DB default puts them; and a null-row must not duplicate/vanish across page boundaries.

- Test cases to list out loud: all-null, no-null, single null at start/middle/end, null + undefined
  mixed, null in the sort key of an object, asc vs desc both, null row on a page boundary.

Q: Why is sorting large data expensive / when NOT to sort?
- CPU O(n log n), memory for copies, network shuffle in distributed sorts.
- Don't sort if you only need min/max (O(n)), top-k (heap), membership (hash set),
  or data is streaming (use Insertion / heap, not a full re-sort).
