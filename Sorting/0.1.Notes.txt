SORTING ALGORITHMS - SUMMARY

Algorithm      | Best       | Avg        | Worst      | Worst SC | Stable | In-place | Online
---------------|------------|------------|------------|----------|--------|----------|-------
Bubble Sort    | O(n)       | O(n^2)     | O(n^2)     | O(1)     | Yes    | Yes      | No
Insertion Sort | O(n)       | O(n^2)     | O(n^2)     | O(1)     | Yes    | Yes      | Yes
Selection Sort | O(n^2)     | O(n^2)     | O(n^2)     | O(1)     | No     | Yes      | No
Merge Sort     | O(n log n) | O(n log n) | O(n log n) | O(n)     | Yes    | No       | No
Quick Sort     | O(n log n) | O(n log n) | O(n^2)     | O(log n) | No     | Yes      | No
Heap Sort      | O(n log n) | O(n log n) | O(n log n) | O(1)     | No     | Yes      | No
Radix Sort     | O(nk)      | O(nk)      | O(nk)      | O(n + k) | Yes    | No       | No
Counting Sort  | O(n + k)   | O(n + k)   | O(n + k)   | O(k)     | Yes    | No       | No
Bucket Sort    | O(n + k)   | O(n + k)   | O(n^2)     | O(n)     | Yes    | No       | No
Shell Sort     | O(n log n) | O(n log n) | O(n^2)     | O(1)     | No     | Yes      | No

Quick recall:
- Only Insertion Sort is ONLINE.
- Stable: Bubble, Insertion, Merge, Counting, Radix, Bucket (impl-dependent).
- Unstable: Quick, Heap, Selection, Shell.
- Not in-place (extra O(n)-ish space): Merge, Radix, Counting, Bucket.


ONLINE vs OFFLINE
-----------------
Offline : needs the ENTIRE dataset upfront; cannot process incrementally.
          Ex: Merge Sort (divide -> sort -> merge), Quick Sort (partition needs full data).
          Use: data already in memory / on disk.

Online  : handles data as it ARRIVES (stream); sort updates in real time per new element.
          Ex: Insertion Sort - each new element inserted into its correct position among already-sorted ones.
          Use: real-time streams, live sensor data, incoming network packets.


STABLE vs UNSTABLE
------------------
Stable  : equal keys keep their INPUT relative order in the output.
          Ex: Merge, Bubble, Insertion, Counting, Radix, Bucket (impl-dependent).
          Why it matters: MULTI-LEVEL sorting (sort by key A, then by key B keeps A-grouping intact).
          Real life: employees sorted by department, then by salary -> same-salary employees stay in department order.
          Tim Sort (Python sorted(), Java Collections.sort()) is stable for exactly this reason.

Unstable: equal keys may get reordered.
          Ex: Quick (most impls), Heap, Selection, Shell.
          When it's fine: order of ties is irrelevant and performance / memory wins.
          Real life: search engine sorting pages by relevance score - ties don't matter, huge input, Quick/Heap are faster.

Can any sort be made stable? YES - at extra time/space cost:
  1. Pair each element with its index: [3, 1, 3] -> [(3,0), (1,1), (3,2)]
  2. Sort with primary key = value, secondary key = original_index (tie-breaker)
  3. Strip the index.
